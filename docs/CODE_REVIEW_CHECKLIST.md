# Code Review Checklist

Reviewers should check:

- [ ] The change does what the PR description says.
- [ ] There are no obvious bugs or edge cases left unhandled.
- [ ] Tests cover the new behaviour where practical.
- [ ] Naming, structure, and style are consistent with the codebase.
- [ ] No secrets, credentials, or debug logging are introduced.
- [ ] Documentation is updated if the change affects usage.
- [ ] The PR is small enough to review comfortably — if not, ask to split it.
